## Как проводить занятия

- Общаться по-русски, объяснять конкретно и небольшими блоками.
- Сначала объяснять новую конструкцию на примере, затем использовать её в заданиях. Пользователь отдельно указал на повторявшуюся ошибку: в упражнения попадало то, что ещё не было объяснено (пример — `list +=`).
- «Есть в шпаргалке», «разобрали» и «пользователь уверенно применяет» — разные состояния. Не считать справочник доказательством освоения тем.
- Пользователь часто пишет «го», «некст», «дальше»: продолжать со следующего шага, учитывая реальный прогресс, а не начинать заново.
- Не навязывать закрепление после каждой темы. Если пользователь говорит, что понял и хочет дальше, двигаться дальше.
- Проверять присланный код, объяснять конкретные ошибки. Звёздочки вокруг имён в сообщениях часто являются форматированием, а не намеренной частью синтаксиса.

## 1. Python: разобранные темы

### Коллекции и объекты

- Основные типы: list, tuple, str, dict, set; изменяемость и хешируемость.
- Ссылки на объекты, присваивание, `==` против `is`.
- Поверхностные копии, общий вложенный объект; назначение `deepcopy`.
- Разница `list +=` и `list +`.
- Накопление сумм через `dict.get`; ключи не могут быть списками.
- Сортировка ключей/пар словаря, сортировка по значениям, `key`, `lambda`, порядок вставки и `items()`.
- Comprehensions для списков, словарей и множеств; генераторные выражения.
- Хеширование, согласованность `__eq__` / `__hash__`, коллизии; как это используется в dict и set. Объект не обязан быть полностью неизменяемым: важно стабильное и согласованное правило хеша/равенства.

### Функции

- `return` против `print`, завершение функции, неявный `None`.
- Изменение переданного объекта против переприсваивания локального параметра.
- Изменяемые значения аргументов по умолчанию; шаблон с `None`.
- Позиционные/именованные аргументы, значения по умолчанию.
- Сбор и распаковка `*args` / `**kwargs`, передача аргументов дальше.
- Области видимости LEGB, `global`, `nonlocal`, `UnboundLocalError`.
- Вложенные функции, функции как значения, замыкания.
- Декоратор-обёртка, смысл `@decorator`, возврат результата исходной функции.
- `functools.wraps`, метаданные `__name__` / `__doc__`, `__wrapped__`.

### ООП

- Класс, экземпляр, `self`, `__init__`, методы и атрибуты экземпляра.
- Атрибуты класса против атрибутов экземпляра; общая изменяемая коллекция у класса.
- Наследование, переопределение, `super()`, базовый полиморфизм.
- Инкапсуляция, соглашение `_name`, преобразование имён `__name`.
- `@property`, сеттер, вычисляемое свойство.
- Композиция и внедрение зависимости через конструктор; оговорка про агрегацию.
- Обычный метод, `classmethod` с `cls`, `staticmethod`.
- `__str__`, `__repr__`, `!r` в f-строке.
- `__eq__`, значение `NotImplemented` против исключения `NotImplementedError`.
- По уточняющему вопросу разобраны соответствия операторов сравнения методам `__eq__`, `__ne__`, `__lt__`, `__le__`, `__gt__`, `__ge__`; обзор арифметических методов, `__iadd__`, `__contains__`, `__getitem__`, `__len__`. `is` / `is not` не перегружаются; для `and` / `or` нет отдельных операторных методов. Самостоятельная реализация сравнений, кроме ранее обсуждённого eq, не проверялась.
- Последствия определения `__eq__` для хешируемости; риски изменения ключей.

### Исключения

- Основные встроенные типы и наследование исключений.
- `try`, `except`, `as`, `else`, `finally`, `raise`, повторное `raise`.
- Назначение `else`: отделить успешное продолжение от области перехвата исключений в `try`. Пользователь сначала не понял, затем получил дополнительный разбор.
- Собственные исключения, наследование от `Exception`, `pass`.
- В шпаргалку добавлен раздел 17 с перечнем встроенных исключений.

### Итерация и данные

- Итерируемый объект против итератора, `iter`, `next`, `StopIteration`, исчерпание.
- Генераторная функция, `yield`, приостановка и продолжение, досрочный `return`.
- Генераторное выражение; отличие функции с `yield` от обычной функции, возвращающей генератор.
- Файлы: `open`, относительный путь от текущей рабочей папки, UTF-8, `with`, режимы r/w/a/x/b.
- `read`, `write`, `readline`, `readlines`, построчная итерация, текущая позиция чтения.
- JSON: преобразование в строку и обратно, чтение/запись файла, ограничения формата и сериализации.
- Модули: собственный файл `.py`, `import module`, `from module import function`, `as`, выполнение верхнего уровня при первом импорте, `__name__`, точка входа через проверку `"__main__"`. Разобрано объяснением, без проверки навыка.
- Пакеты: обычный пакет с `__init__.py`, абсолютные и относительные импорты, `python -m`, отличие прямого запуска файла от запуска модуля в пакете. Разобрано объяснением, без проверки навыка.
- Окружение и зависимости: venv, активация в PowerShell и прямой вызов python.exe, pip через `python -m`, freeze/requirements, восстановление и deactivate; отличие фиксации установленных версий от полноценной гарантии воспроизводимости. Только объяснение; окружение не создавалось.
- Собственные контекстные менеджеры: `__enter__` и значение после `as`, аргументы и результат `__exit__`, обработка/передача исключения, аналогия с очисткой в finally; ошибка в enter не запускает exit этого менеджера. Только объяснение.
- Аннотации типов: параметры и результат, переменные, типизированные контейнеры, объединение типов через `|`, возможный None, различие подсказки и значения по умолчанию, отсутствие встроенной автоматической runtime-проверки. Только объяснение.
- Основы тестирования: assert и AssertionError, ожидаемое поведение, обычные/ошибочные/граничные случаи, отсутствие изменения входных данных, структура подготовки/действия/проверки. Важно: assert не заменяет проверки входных данных, может отключаться через -O. Только объяснение.
- unittest: TestCase и test_* методы, assertEqual, assertRaises через with, запуск python -m unittest -v test_numbers, результаты ok/FAIL/ERROR и отличие assert-методов от отключаемого assert. Только объяснение.
- Traceback: чтение типа/сообщения снизу, строки сбоя и цепочки вызовов, поиск источника неверных данных, не заменять отсутствующие обязательные данные произвольным default без понимания требований. Только объяснение.
- Отладчик: breakpoint() по умолчанию включает pdb; p/ n/ s/ c/ l/ w/ q, значения и выражения в контексте остановки. Разобрано объяснением; отладчик за пользователя не запускался.
- Logging: настройка через basicConfig и getLogger(__name__), уровни и порог, отложенная подстановка параметров сообщения, logger.exception с traceback внутри except; методы логгера сами по себе не возбуждают описываемое исключение. Только объяснение.
- Асинхронность: async def / объект корутины, asyncio.run, await и неблокирующая пауза asyncio.sleep, event loop, последовательное ожидание двух вызовов. Подчёркнуто: переключение не гарантировано при каждом await, а async не ускоряет вычисления автоматически. Только объяснение.
- Уточнение по await: при ожидании приостанавливается текущая корутина, управление может перейти event loop; весь поток не блокируется этим ожиданием. Сравнили с JS: вызов async-функции Python создаёт корутину без запуска, а asyncio.run ждёт её завершения на уровне обычного кода.
- Конкурентность: gather с корутинами, порядок результатов, Task через create_task, ожидание ранее запущенных задач. Различены конкурентное ожидание и одновременные вычисления на ядрах. Только объяснение.
- Блокирующие операции: time.sleep в async блокирует event loop; await asyncio.sleep не блокирует ожиданием поток; asyncio.to_thread(sync_function, *args) переносит обычную блокирующую функцию в поток, не вызывать её заранее в аргументе. Только объяснение.
- Обзор конкурентности: I/O-bound/CPU-bound, asyncio/threads/processes, GIL относится к конкретной реализации/сборке; free-threaded CPython существует с 3.13, нативный код может освобождать GIL. GIL не заменяет согласование общих данных, показан threading.Lock через with. У процессов обычно отдельная память и есть затраты на запуск/обмен. Только объяснение.
- Конфликт имени собственного модуля со стандартным: в установленной сборке Anaconda `math` встроен в интерпретатор и выбирается раньше локального `math.py`. Разобрано на ошибке импорта; предложено переименование в `my_math.py`, применение исправления пользователем пока не проверено.
